# 工作流页面 UI 文案统一记录

## 目标

将工作流管理页面所有用户可见界面统一为通俗、明确的中文表达，同时保留 API、数据库及调试所需的技术标识。

## 本次范围

- 工作流列表、创建表单、详情治理信息。
- 版本、定义、运行、审计、运行链路标签及操作。
- 加载失败、校验失败、创建、发布、运行、取消、重试、恢复提示。
- 后端状态值通过前端显式映射为中文，避免枚举值直接暴露给普通用户。
- 审计操作和运行链路事件提供中文展示名称。
- 空状态、输入提示和确认弹窗统一中文。

## 技术标识保留原则

工作流 ID、版本 ID、运行记录 ID、节点 ID、错误代码以及 JSON 内容属于诊断或协议数据，不进行臆造式翻译，保持后端返回值。

## 实现原则

1. 不修改 `workflowApi` 接口和后端数据结构。
2. 用户看到的标签、按钮、说明、状态和错误提示默认使用中文。
3. 后端枚举值不直接渲染到用户界面，通过显式映射转换为中文。
4. 新增状态必须同步补充状态映射与页面测试。
5. 新增用户可见英文术语必须在评审中说明，否则视为 UI 文案回归。

## 测试约束

`frontend/tests/views/Workflows.test.ts` 覆盖中文空状态、状态映射、运行记录、恢复运行以及旧英文术语回归。后续工作流 UI 改动至少运行该页面定向测试，并在提交前纳入全量测试和构建门禁。
