# P1.3 Runtime ↔ Workflow 生命周期双向深链

## 1. 目标

在 P1.2 Workflow 生命周期工作台已经能够携带真实 `execution_id`、`workflow_id`、`workflow_version_id` 进入 Runtime 的基础上，补齐反向导航：Runtime 在存在真实 `workflow_id` 时，可以返回 Workflow 生命周期工作台，并由目标页面使用该 ID 恢复对应 Workflow。

本切片只解决跨页面上下文恢复，不复制 Workflow/Execution 状态机，也不新增后端接口。

## 2. Backend Contract 对齐

本切片继续使用现有正式 Contract：

- `GET /workflows`：生命周期页面取得 Workflow 列表及 `Workflow.name`。
- `GET /workflows/{id}/versions`：取得版本事实。
- `GET /workflows/{id}/triggers`：取得触发器事实。
- `GET /workflows/{id}/triggers/{trigger_id}/schedule`：取得定时调度事实。
- `GET /workflows/{id}/executions`：取得 Workflow Execution 事实。
- Runtime 既有查询接口继续由 `RuntimeExecutions` 使用；本切片不新增 Endpoint。

关键约束：`workflow_id` 必须来自真实 Runtime 路由上下文或后端返回的 Execution 数据；前端不得通过 Execution ID、页面文本或其他字段推断 Workflow。

## 3. 实现

### Workflow 生命周期入口

`WorkflowLifecycle.vue` 读取路由 query 的 `workflow_id`。加载 Workflow 列表后：

1. query 中存在且属于服务端返回列表的 ID → 选择该 Workflow；
2. query ID 不存在或无效 → 回退到当前页面原有的首个 Workflow 选择策略；
3. 后续详情请求继续以最终选中的真实 Workflow ID 为参数。

这样可以兼容普通入口和 Runtime 深链入口，同时避免通过 query 直接扩大可访问资源范围。

### Runtime 反向入口

`RuntimeWorkspaceTabs.vue` 在存在 `workflow_id` 时显示“返回 Workflow 生命周期”按钮。

点击后只携带：

- `workflow_id`：真实 Workflow 资源 ID；
- `source=runtime`：导航来源标识。

目标地址为 `/workflows/lifecycle`。不携带 Runtime 的 Execution/Trace 等无关参数，避免把运行时上下文错误地当成 Workflow 状态。

## 4. UI / 响应式设计

- 返回入口放在 Runtime 工作台标题区，与当前 Tab/上下文标签保持同一信息层级。
- Workflow 页面保持既有企业级信息架构，不新增重复详情面板。
- Runtime 标题区使用 `flex-wrap`，窄屏下按钮与上下文标签自动换行。
- 没有 `workflow_id` 时不展示返回入口，也不会构造无效 Workflow 链接。

## 5. 测试覆盖

新增/调整 Vitest：

- Workflow 深链 `workflow_id` 可以恢复真实 Workflow；
- 恢复后 versions / executions 请求使用真实 Workflow ID；
- Runtime 存在 `workflow_id` 时生成正确的 Workflow 生命周期路由；
- Runtime 缺少 `workflow_id` 时不生成无效导航；
- 保留原有 Runtime Tab 深链和 Workflow → Runtime Execution 上下文测试。
