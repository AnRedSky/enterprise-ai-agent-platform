# P2.10-I Runtime Operations Console 前端实现记录

## 1. 基线

- 基线分支：`main`
- 后端当前阶段：Phase 2.10-I Runtime Notification Lifecycle / Provider / Metrics / Alert / Export / Operational Audit
- 前端本次交付：Runtime Operations Console 第一阶段收口
- 原则：以后端已经存在的 HTTP Contract 为唯一事实来源，不在前端复制告警、SLO、Provider 路由或状态计算规则。

## 2. 本次实现

`/runtime/operations` 由原来的 Event / Delivery / SLO / Dead Letter 总览扩展为六个运维域：

1. **总览**：Event、Delivery、死信、投递成功率、错误预算、P95。
2. **告警**：Alert 生命周期实例、Alert Rule、启停规则、显式评估。
3. **Provider**：Provider 列表、启停、健康探测；页面不展示 Secret。
4. **Metrics**：按后端 metric name 与 dimension Contract 查询时间序列，并支持创建采样快照。
5. **Audit**：Runtime 运维动作审计。
6. **死信**：查询 dead-letter Delivery，并通过后端 batch replay Contract 重新入队。

## 3. Contract 映射

| 前端能力 | 后端接口 |
|---|---|
| 总览 | `GET /runtime/operations/overview` |
| Alert 实例 | `GET /runtime/operations/alerts` |
| Alert Rule | `GET/PATCH /runtime/operations/alert-rules` |
| Alert 评估 | `POST /runtime/operations/alert-rules/evaluate` |
| Provider | `GET/PATCH /runtime/operations/providers` |
| Provider 健康 | `POST /runtime/operations/providers/{provider_id}/health` |
| Metrics Snapshot | `POST /runtime/operations/metrics/snapshot` |
| Metrics Series | `GET /runtime/operations/metrics/series` |
| Operational Audit | `GET /runtime/operations/audit` |
| Dead Letter | `GET /runtime/operations/dead-letters` |
| Dead Letter Replay | `POST /runtime/operations/dead-letters/replay` |

## 4. 设计决策

- 所有运维数据通过 `frontend/src/api/runtimeOperations.ts` 统一封装，页面禁止直接散落 `request.get/post/patch`。
- 前端只负责展示、交互确认和导航，不重新计算 Provider fallback、dedup、cooldown、SLO 或 Alert 生命周期。
- Provider / Alert Rule 状态切换失败时恢复原 UI 状态，避免出现“界面已成功、后端实际失败”的假状态。
- 死信重新投递继续经过后端 Worker 队列，浏览器绝不直接请求 Destination。
- 页面采用 Tab 分域，降低企业运维场景的信息密度；移动端允许工具栏和 Metrics 查询表单纵向排列。
