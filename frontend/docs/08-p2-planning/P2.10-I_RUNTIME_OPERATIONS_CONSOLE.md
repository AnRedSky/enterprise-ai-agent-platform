## 2. 后端 Contract 对齐

新增只读接口：

| 能力 | HTTP | 查询参数 | 前端类型 |
|---|---|---|---|
| Worker 诊断 | `GET /api/v1/runtime/diagnostics/worker` | `window_hours=1..168`、`limit=1..100` | `RuntimeWorkerDiagnostics` |
| Scheduler 诊断 | `GET /api/v1/runtime/diagnostics/scheduler` | `limit=1..100` | `RuntimeSchedulerDiagnostics` |

后端明确返回 `liveness` 与 `liveness_reason_code`。当前没有 Durable Heartbeat Fact 时，值为 `unknown`，前端只展示该事实，不根据 claim、lease、frontier 或 trigger 活动推断“健康”。

### Worker

- `frontier`：total、status_counts、running、pending、completed、failed。
- `leases`：without_expiry、active、expired。
- `owners`：真实 `worker_owner` 与 claim_count 聚合。
- `recent_errors`：真实 Frontier / Execution ID、attempt、worker owner、error_code 与时间。

### Scheduler

- `durable.enabled_scheduled_triggers`：启用的 Schedule Trigger 数量。
- `durable.disabled_scheduled_triggers`：停用的 Schedule Trigger 数量。
- `durable.pending_frontier_items`：持久化待处理 Frontier 数量。
- `triggers`：真实 Schedule Trigger ID、Workflow ID、名称、状态、配置摘要和更新时间。

## 3. 前端实现

新增 `frontend/src/api/runtimeDiagnostics.ts`：

1. 集中封装 Worker / Scheduler Diagnostics HTTP 调用。
2. 类型结构与后端 Pydantic Schema 对齐。
3. 不接受或发送客户端 `tenant_id`，租户边界由认证上下文和后端 API 负责。

`GlobalRuntimeOperations.vue` 增加“Worker / Scheduler 诊断”区域：

- Global Runtime posture 与 Diagnostics 并行请求，避免诊断失败阻断核心运行态势。
- Worker 展示 Claim / Lease、Owner 聚合及最近错误。
- Scheduler 展示 Durable backlog 与 Schedule Trigger 摘要。
- `unknown` 状态显示中文“未知”，同时保留后端 `liveness_reason_code` 作为诊断信息。
- 不展示 Secret、Token 或 Provider 敏感配置。
- 900px/1100px/720px 断点下自动从双列降为单列/紧凑网格，保持移动端可读性。

## 4. 交互与错误边界

- Global posture 请求失败：页面进入明确错误状态，并提供刷新动作。
- Diagnostics 单独失败：保持 Global Runtime posture 可用，仅提示“诊断数据暂时不可用”。
- 刷新或切换窗口时同时刷新 posture、Worker、Scheduler 三份快照。
- 所有诊断表格均有空状态，不使用假数据填充。

## 6. 手动验收流程

1. 安装项目锁定依赖，不使用 `npx` 临时下载测试框架。
2. 在已具备有效认证上下文的本地环境进入 `/runtime/operations/global`。
3. 确认 Global Runtime posture 正常显示 Execution、Workflow、Worker、Scheduler 数据。
4. 确认“Worker / Scheduler 诊断”正常显示 Owner、Lease、最近错误和 Schedule Trigger。
5. 确认无心跳事实时显示“未知”，并能看到 `NO_DURABLE_HEARTBEAT_FACT`，不能显示为“健康”。
6. 切换 1 小时 / 24 小时 / 7 天，确认 Worker 查询的 `window_hours` 同步变化，Scheduler 继续只使用其正式 `limit` Contract。
7. 使用自动化 mock/fixture 注入 Worker 或 Scheduler 请求失败，确认 Global posture 仍可使用且不显示原始异常文本。
8. 在 1100px、720px 和桌面宽度检查诊断区域的响应式布局。
9. 最后按项目标准执行 targeted Vitest → 全量 Vitest → build → `test:gate`。
