# 前端 UI 文本规范

## 1. 目标

统一企业 AI 智能体平台前端界面的中文表达，让普通业务用户、运维人员和管理员能够直接理解页面含义，不需要先理解英文技术术语。

本规范适用于 `frontend/src` 下所有用户可见文本，包括页面标题、菜单、标签、字段、按钮、筛选条件、状态、提示、确认框、空状态、错误信息和帮助说明。

## 2. 核心原则

### 2.1 用户界面统一使用中文

用户可见的界面文本默认必须使用中文。禁止直接使用英文技术名称作为页面标题、按钮、字段名称或操作名称。

推荐：

- `事件观察`
- `投递管理`
- `事件类型`
- `投递目标`
- `查看审计记录`
- `重新投递`

不推荐：

- `Integration Event`
- `Delivery Operations`
- `Event Type`
- `Destination`
- `Audit`
- `Replay`

### 2.2 技术值可以保留原文

协议值、数据库值、错误码、事件类型值、资源 ID、Trace ID、Request ID 等机器可识别内容可以保留原始格式。例如：

- `workflow.execution.completed`
- `HTTP_ERROR`
- `trace-xxxx`
- `request-xxxx`

但这些值对应的 UI 字段名称必须使用中文，例如“事件类型”“最近错误”“链路追踪 ID”“请求 ID”。

### 2.3 优先表达用户动作和结果

按钮使用用户能够立即理解的动作描述，而不是技术实现名称。

| 技术名称 | UI 文案 |
| --- | --- |
| Replay | 重新投递 |
| Audit | 查看审计记录 |
| Refresh | 刷新 |
| Create Destination | 新建投递目标 |
| Create Subscription | 新建事件订阅 |
| Payload | 事件内容 |
| Metadata | 附加信息 |

### 2.4 状态使用统一中文

状态必须通过统一映射向用户展示，后端枚举值不得直接作为状态标签展示。

| 后端值 | 中文显示 |
| --- | --- |
| pending | 待处理 / 待投递 |
| processing | 处理中 |
| delivering | 投递中 |
| delivered | 已送达 |
| retrying | 重试中 |
| failed | 失败 / 处理失败 |
| dead_letter | 进入死信 |

如果同一个状态在不同业务场景中含义不同，应选择最贴合当前业务动作的中文，而不是机械翻译。

### 2.5 错误信息说明“发生了什么”和“下一步怎么办”

错误提示尽量采用：`发生了什么 + 用户可以怎么做`。

推荐：

> 数据加载失败，请刷新后重试。

不推荐：

> Request failed.

后端返回的错误码可以作为辅助信息保留，方便排障，但不应成为普通用户唯一能看到的说明。

## 4. 页面文本规范

### 页面标题

使用简短的业务名称，避免堆叠英文技术概念。

### 字段名称

描述用户看到的数据是什么，例如“目标地址”“最近错误”“发生时间”，而不是直接使用接口字段名。

### 按钮

使用动词开头并明确结果，例如“创建”“保存”“查看详情”“重新投递”。

### 空状态

不要只显示“暂无数据”，在需要时补充下一步操作，例如“暂无投递目标，请先创建投递目标”。

### 确认框

说明操作对象、当前状态和操作结果，例如“确认重新投递该记录？系统会重新进入可靠投递流程。”

### 帮助说明

使用短句解释业务意义，避免把后端实现细节直接搬到页面。

## 5. 技术字段与中文 UI 的边界

前端 Contract、TypeScript 类型、API 参数、路由名称和后端枚举不要求改成中文，因为它们属于代码层协议。修改范围只针对用户可见文本。

例如：

```ts
filters.status = "dead_letter"
```

代码可以保持不变；页面应该显示“进入死信”。

同样，事件类型 `workflow.execution.completed` 应保持原值，页面字段名称显示“事件类型”。

## 6. 开发检查清单

提交前逐项检查：

- [ ] 页面标题是否为中文。
- [ ] 菜单和标签是否为中文。
- [ ] 按钮是否为明确的中文动作。
- [ ] 表格字段是否为中文。
- [ ] 状态是否进行了中文映射。
- [ ] 空状态是否容易理解。
- [ ] 错误提示是否说明了问题及下一步操作。
- [ ] 确认框是否说明操作影响。
- [ ] 技术 ID、事件类型、错误码等原始值是否仍保持可排障性。
- [ ] 是否避免为了中文化而修改 API Contract、枚举值或数据库字段。

## 7. 本次落地范围

本次首先修正集成中心相关页面：

- 投递目标
- 事件订阅
- 事件观察
- 投递管理
- 投递审计记录
- 创建配置对话框
- 查询条件和状态
- 错误、空状态及操作提示

后续新增页面必须直接遵循本规范；已有页面按照前端 UI 优化计划逐步迁移，不要求一次性大范围重构业务代码。
