# 前端异常提示统一规范

## 目标

统一处理后端异常、HTTP 状态和错误消息，避免用户界面直接展示英文框架异常或 HTTP 原始文本。

## 规则

1. 用户可见提示统一使用通俗中文。
2. HTTP 4xx/5xx 原始文本不直接展示。
3. 401、403、404、409、422、429 使用固定中文提示。
4. 5xx 统一提示服务暂时不可用，技术错误代码仍由业务页面按需单独展示。
5. 后端业务消息在明确可读且非 HTTP 原始错误时可以保留。
6. 未知错误使用调用方提供的中文兜底文案。
7. 技术标识（错误代码、请求标识、链路标识、资源 ID）与用户提示分离，不能用技术标识替代用户提示。

## 实现

`frontend/src/utils/errorMessage.ts` 提供统一转换函数 `toUserErrorMessage`。

Axios 全局响应拦截器统一改写 `error.message`，因此已有页面即使使用 `e instanceof Error ? e.message : ...`，也不会再次把 HTTP 原始异常直接呈现给用户。

## 回归要求

新增或修改页面时，应至少覆盖：

- HTTP 401/404/5xx 不出现英文原始异常；
- 后端业务错误可读时保留中文业务提示；
- 无法识别的异常使用中文兜底提示；
- 技术错误代码需要展示时，代码单独保留，不作为用户提示正文。
