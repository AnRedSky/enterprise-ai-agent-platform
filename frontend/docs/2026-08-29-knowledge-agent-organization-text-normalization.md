# 前端用户可见文本统一：Knowledge / Agent / Organization

## 目标

在不改变既有页面结构、接口契约和业务行为的前提下，统一用户可见文本为通俗易懂的中文。后端状态、错误码、请求标识、URI、模型 ID 等技术标识继续保留，用于排障和运维，但不再直接作为主要界面文案。

## 本轮完成

### Knowledge

- 页面标题、说明、操作按钮统一为中文。
- `status`、`ingestion_status` 不再直接渲染，统一映射为中文状态，并在必要时保留后端值，例如“已启用（active）”。
- `source_type` 统一映射为中文来源类型，并保留原始值。
- `lexical-v2`、`vector`、`hybrid` 统一显示为“关键词检索 v2（lexical-v2）”“向量检索（vector）”“混合检索（hybrid）”。
- `Score`、`Mode`、`Sources`、`Citation`、`Source URI` 等技术概念改为中文主文案，并以括号保留技术标识。
- `Chunk / Chunks / Ingest / Retrieval Debug` 改为中文操作描述，同时保留必要技术标识。
- 加载、创建、删除、版本处理、分块加载、检索等异常不再直接展示后端异常文本。
- 修正知识库回归测试的组件引用，使测试直接覆盖实际 `KnowledgeWorkbench.vue`。

### Agent

- 既有状态映射、运行标识中文化保持不变。
- 列表、创建、版本管理、发布、归档、对话执行等异常统一使用稳定中文兜底，不再透传 HTTP 或后端英文异常。
- 回归测试同时覆盖 HTTP 异常和普通后端英文异常。

### Organization

- 组织和成员状态统一中文，并保留原始状态值。
- 成员角色统一为“所有者 / 管理员 / 成员”，并保留技术值。
- `User ID` 改为“用户 ID（User ID）”。
- 组织列表、组织详情、成员管理、状态更新、角色更新、移除和所有权转移均使用中文错误兜底。
- 保留 403 / 404 的明确中文业务提示。
- 回归测试同时覆盖 HTTP 异常和普通后端英文异常。

## 统一规则

1. 用户主要看到中文；英文只作为必要技术标识的括号补充。
2. 后端 `status`、`error_code`、`type`、`mode` 等枚举不得直接渲染。
3. `Error.message` 不得直接作为用户提示；应映射为稳定、易懂的中文文案。
4. 请求 ID、链路追踪 ID、会话 ID、执行 ID、URI、模型 ID 等排障信息可以保留，但必须有中文标签。
5. 页面结构、接口参数、后端契约和业务操作不因中文化发生改变。

## 回归测试要求

每个页面至少覆盖：

1. 正常状态的中文显示。
2. 未知状态的中文兜底。
3. 后端英文异常不会直接展示给用户。
4. 技术标识仍可追踪。
5. 页面原有业务操作和接口调用保持不变。

## 本轮验证范围

- KnowledgeWorkbench：中文文案、状态映射、检索方式映射、异常兜底。
- AgentWorkbench：生命周期状态、运行标识和异常兜底。
- Organizations / OrganizationDetail：状态/角色映射、技术标识中文标签、异常兜底。

## 后续扫描

继续对 `frontend/src/views`、公共组件和 API 错误处理进行源码级扫描，重点检索 `error.message`、直接 `status` 渲染、`error_code`、英文枚举和英文用户提示。新增页面必须遵循本规范，不再通过复制“中文版 UI”解决问题，而是在现有页面上只替换用户可见文本和状态/错误映射。
