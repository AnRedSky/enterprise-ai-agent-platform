# Backend 模块重构：兼容垫片方案纠偏

## 1. 发现时间

2026-08-23

## 2. 问题

Backend 目录重构第一轮曾采用旧 `app/services/agent_registry.py` 保留为新领域模块的兼容转发入口。

该方式虽然可以降低短期 import 风险，但与当前项目最终目标不一致：本次任务要求的是彻底完成领域模块化重构，而不是长期保留旧模块路径。

## 3. 影响

如果继续保留兼容垫片，会产生以下工程问题：

- 旧目录结构无法真正收敛；
- 新旧模块路径同时有效，增加依赖复杂度；
- 无法通过旧路径搜索判断迁移是否真正完成；
- 后续新代码可能继续引用旧路径；
- 模块边界整改只能停留在表面目录变化。

当前没有证据表明该垫片已经改变业务行为；问题属于架构实施方式错误。

## 4. 纠正措施

已将实施规则调整为：

```text
领域拆分
 ↓
生产代码 import 全量切换
 ↓
测试 import 全量切换
 ↓
删除旧文件
 ↓
全仓旧路径搜索 = 0
 ↓
领域测试
 ↓
Backend Regression
```

禁止：

```text
旧模块 → 新模块转发
旧实现 + 新实现并存
旧目录长期保留
```

同时同步更新：

- `docs/DEVELOPMENT.md`；
- `docs/00-architecture/BACKEND_MODULE_ARCHITECTURE.md`；
- `docs/00-architecture/BACKEND_MODULE_MIGRATION_MAP.md`；
- `docs/PROJECT_STATUS.md`。

## 5. 预防措施

以后每个领域迁移必须将“旧文件删除”和“全仓旧路径搜索”为硬性验收条件；未满足条件不得记录为迁移完成。
